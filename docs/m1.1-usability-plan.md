# M1.1 — Vault usability implementation plan

Status: U01–U39 implemented and installed on Linux. Automated integrity checks and the installed-app smoke below passed. Certification is limited to the recorded evidence; it is not a claim that every manual scenario or operating system was exercised.

## Goal and boundary

Complete this workflow without an external file manager: create folders and Notes, import documents, organize and link them, recover a deletion, find content, work across documents, and resume after closing or crashing the app.

All capabilities proposed in the usability discussion are in scope. Delivery is incremental; later waves are not optional scope cuts. Keep native pickers for selecting a Vault and importing external files. Preserve optional external opening. Do not build a whole-filesystem browser, PDF/DOCX editors, OCR, cloud synchronization, cross-Vault operations, or a generic undo engine for filesystem operations. Saving source remains explicit; draft recovery is not autosave.

## Existing implementation to extend

- Native authority: `native/src/vault/commands.rs`, `commands/session.rs`, `commands/background.rs`, `capability.rs`, `persistence.rs`, `notes.rs`, `metadata.rs`, and `lifecycle.rs`.
- Incremental inventory: `indexing.rs` and `indexing/work/`; current ceilings include 50,000 entries, 2,048 watched directories, 256 KiB metadata reads, and 32 MiB inventory batches. Index states already distinguish incomplete/stale/cancelled results.
- Workspace orchestration: `ui/features/workspace/useWorkspace.ts`, `buffer.ts`, `useDirectoryPages.ts`, `workspaceEvents.ts`, and `types.ts`. The current single-buffer coordinator must not grow into a multi-feature monolith.
- Surfaces: `VaultExplorer.tsx`, `ui/app/ExplorerSidebar.tsx`, `WorkspaceTabs.tsx`, `WorkspaceRibbon.tsx`, `DocumentWorkbench.tsx`, `DocumentPanes.tsx`, and feature CSS.
- Editor: CodeMirror in `ui/features/markdown/`; preserve source, BOM, line endings, metadata, selection, and undo history.
- Existing local preference: `commands/remembered.rs` owns `last-vault.json`. Keep its close-versus-exit semantics; do not introduce a competing active-Vault preference.
- Registration boundary: `native/src/lib.rs`, `native/build.rs`, and `native/capabilities/main.json` must change together for each new command.
- Delivery boundary: `bun run app:update` builds and replaces the executable referenced by the desktop launcher. A development build alone does not update the installed app.

## Non-negotiable safety contracts

### Authority, identity, and source

1. Native commands accept paths relative to the active content root, never arbitrary frontend filesystem authority. Keep no-follow capabilities and root/manifest verification.
2. Return and check session generation for asynchronous results. Opening another Vault invalidates pending plans, directory/search requests, cut/copy state, and session writes for the previous Vault.
3. Normalize identity handling through existing metadata code. Rename/move preserves UUID; independent duplication creates new UUIDs and remaps references within a duplicated subtree. References to content outside that subtree keep their original identities.
4. Do not change the semantics of existing recovery `save_copy`, which intentionally preserves source and UUID. Duplication is a distinct user operation.
5. Original bytes, unsupported files, unknown metadata, BOM, and mixed line endings survive operations. Invalid metadata is never guessed into valid data: refuse an identity-sensitive duplication/adoption with an actionable result when safe identity handling is impossible.
6. No wildcard filesystem permission. Drop events and native pickers grant bounded import capabilities; text from a browser drag payload is not a trusted absolute path.
7. Newly introduced folders/metadata may not hide or overwrite a user's existing directory. Legacy container-relative Vaults receive explicit namespace collision handling.

### Multi-file changes and recovery

A rename of a referenced Note is not a single `rename()` call. Companion files, inbound links, outgoing relative links, open buffers, and index entries participate.

- Introduce a native prepare/commit flow for destructive or multi-file mutations. Preparation returns an opaque plan ID bound to the current generation and expected source revisions, plus affected paths, physical item counts, conflicts, hidden/unsupported counts, and dirty-referrer candidates.
- The frontend resolves dirty-buffer decisions and requests a new plan if those decisions changed source revisions. Native commit revalidates authority, all relevant revisions, destination exclusivity, and the plan; a plan is not a lock over the external filesystem.
- Reserve commit ordering per Vault. Serialize internal mutations, not the UI thread. Do not hold the session mutex while walking files, hashing, or rewriting references.
- One logical operation uses staged bytes and a small recoverable journal. Ordinary filesystems do not provide a multi-file transaction: never claim global atomicity. On interruption, reconcile journal state before admitting conflicting writes; retain all versions needed for recovery. Do not roll back over a newer external write.
- Store recognized administrative trash/transaction content under a marked `.adamant/` directory in the Vault container, outside `content/` for new Vaults. It is authoritative recovery content, not disposable SQLite cache. For legacy Vaults, exclude it only after validating Adamant's ownership marker. An unrelated preexisting `.adamant` directory blocks creation of this namespace with a clear error; it must not be adopted or hidden.
- Trash records retain original relative location, identity, time, payload, and companions. Use same-filesystem rename when safe; cross-filesystem fallback must verify a staged copy before removing the original. Restoration and purge use the same capability and revision checks.
- No silent expiry of trash or drafts. Purge requires explicit confirmation. Recovery metadata is bounded; large operations report limits before deletion.
- Batch operations are atomic only at the logical-item level supported by their recovery protocol. Return completed, failed, skipped, and unstarted/cancelled items. Stop safely at operation boundaries; do not promise undo of already completed items.
- Deduplicate a selected parent and its descendants, reject movement into self/descendant, protect the Vault root and administrative metadata, and handle case-only rename without an overwrite window.

### Link rewriting

- Resolve old targets before moving and recompute paths from each referrer's final location. Include inbound and outgoing Markdown links/images, reference definitions, directory moves, spaces, Unicode, URL escaping, and fragments.
- Ignore code spans/fences, external URLs, and unrelated source. Structured UUID references survive moves; duplication remaps only the duplicated identity set.
- Use syntax-aware parsing with source offsets, not a broad regex or parse-and-reserialize formatting pass. Main must approve the smallest suitable parser/dependency after checking the existing stack.
- A complete reference-impact assessment is required before claiming a safe move. If inventory/reference coverage is partial, run bounded cancellable reconciliation; if coverage remains insufficient, block the move and explain why. Do not ship a silent 'move anyway and break links' fallback.
- Check dirty incoming-link documents as well as the moved document. Clean open tabs receive committed content and new revisions; dirty tabs require Save/Discard/Cancel before mutation, never blind replacement.
- Trashing a target leaves incoming references unresolved rather than deleting or redirecting them. Restoration makes them resolvable again where identity and paths match.

### Resource and persistence policy

- Retain existing inventory/file ceilings. Enumerate actual recursive mutation scope separately with bounded traversal; reaching a limit means 'incomplete', never 'empty' or 'safe to delete'. Preflight stops before mutation if safe scope cannot be established.
- Search runs off the UI thread, supports cancellation, and does not read the entire Vault into memory per keystroke. Start with the existing inventory for name/path search and a bounded incremental content index for Markdown. Verify FTS5 support in the shipped SQLite before choosing it; document a bounded alternative if unavailable. No unbounded fallback scans.
- Proposed initial query budget: 50 hits/page, up to 500 returned occurrences per query, with explicit truncation and paging semantics. Freeze content indexing byte/storage ceilings using a real large-file fixture in Wave 0; do not silently index only a prefix and label coverage complete.
- Preserve CodeMirror state across tab switches; lazy-mount heavy viewers and release clean PDF/DOCX resources when inactive. Never silently evict unsaved buffers. Establish measured aggregate memory limits and warn before refusing an additional large document.
- Persist session/preferences with versioned, bounded, atomic native writes. Coalesce updates; flush at safe lifecycle boundaries. Malformed state must not prevent opening the app or rewrite source.
- Draft snapshots retain raw source, base revision, identity and path, and a timestamp. Debounced writes plus focus/close flush bound the recovery window; publish the measured interval and expose write failures. Recovery cannot promise every keystroke after abrupt power loss.
- On restore, apply recovered text only after user choice. If the base source changed, retain both versions and use the existing conflict/recovery workflow. Discard removes the applicable draft only after explicit intent; successful save clears only the matching snapshot, not a newer edit.
- Favorites/recents are per-Vault local navigation preferences, not cross-Vault links. Follow confirmed mutation mappings and report unresolved targets. This does not redefine authored portable references.
